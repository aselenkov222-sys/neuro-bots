# План разработки

Технические решения и порядок работ. Поведение продукта — в [глоссарии](glossary.md), [модели](domain.md), [потоках](flows.md) и [границе MVP](out-of-scope.md).

<a id="stack"></a>

## Стек

Сервер и десктоп пишутся на Python 3.15. В `requires-python` стоит `>=3.15,<3.16`. Телефон — отдельное приложение и в эту очередь не входит.

Сервер — FastAPI. Кабинет и будущий десктоп ходят в один JSON API. FastAPI отдаёт статику кабинета и JSON с одного origin.

База — PostgreSQL. Таблицы ведёт SQLAlchemy 2.0, миграции — Alembic, драйвер — psycopg 3. Поддержка Python 3.15 у SQLAlchemy есть с 2.0.52.

Локально PostgreSQL поднимается в Docker, сервер запускается через uv. Общий стенд появляется, когда кабинетом пользуется человек снаружи команды.

Пароль хранится хешем Argon2 через `pwdlib` 0.4.0.

Репозиторий один.

- `server/` — сервер на uv.
- `web/` — кабинет: HTML, CSS и JS из макета, без прототипной шапки.
- `mockup/` — просмотр макета. Сервер его не отдаёт.
- `desktop/` — появляется вместе с macOS.

<a id="checkpoint-1"></a>

## Первый checkpoint

Кабинет в браузере. Экраны: регистрация, вход, тариф, список ботов, карточка, чат. Карточка сохраняет имя, аватар, описание и сценарий. Набор аватара берётся из макета. Пара по умолчанию — цвет «Ржавый» (`#c85a12`) и значок «Искра» (`spark`). Экран пароля подключается на macOS вместе с хранилищем. Рутина, библиотека, главный бот, «Да» и «Нет», бейдж рабочего десктопа и оплата в этот checkpoint не входят.

### Путь пользователя

Регистрация по почте и паролю сразу открывает сессию. До подтверждения почты виден только экран тарифа. Ссылка подтверждения одноразовая и живёт 24 часа. В разработке она берётся из журнала сервера. Почтовый провайдер подключается, когда на кабинет приходит человек снаружи команды.

Повторное открытие и открытие после 24 часов почту не подтверждают. На тарифе виден текст «Ссылка больше не действует». Кнопка «Прислать новую» доступна, пока почта не подтверждена: она пишет в журнал новую ссылку и гасит прежнюю. Письмо наружу не отправляется.

Почта сохраняется без пробелов по краям и в нижнем регистре. Уникальность проверяется по этому виду.

После подтверждения в разработке период подписки становится активным. На проде на этом месте остаётся оплата, как в [потоках](flows.md).

Период — календарный месяц от даты старта. Старт 16 ноября кончается 16 декабря. Если этого числа в месяце нет, период кончается в последний день месяца.

В конфиге разработки один тариф без названия и цены: 500 запросов к модели и 5 рутин на период. Перед релизом числа, название и цену задаёт владелец продукта.

Дальше открывается пустой список ботов. С экрана тарифа и из кабинета доступен выход. Он удаляет только текущую сессию.

Имя профиля хранится в учётной записи, до 80 символов, и может быть пустым. Экран его правки в этот checkpoint не входит.

### Сессия и пароль

Каждый вход создаёт свою сессию. Кабинет и будущий десктоп могут быть в аккаунте одновременно. Выход на одном устройстве другое не разлогинивает.

Сессия живёт 30 дней с последнего успешного запроса.

Пароль — от 8 до 128 символов. В нём есть хотя бы одна цифра `0–9` и хотя бы один знак из набора `` !@#$%^&*()-_=+[]{}:;,.? ``.

Идентификатор сессии лежит в PostgreSQL. Браузер получает только его в cookie `HttpOnly` и `SameSite=Lax`. JavaScript cookie не читает. Изменяющий запрос принимается только с Origin нашего сервера. Флаг `Secure` включается на общем стенде.

### Данные

Первая миграция: учётная запись, ссылка подтверждения, сессия, период подписки, счётчик квоты, запись списания, бот, чат, сообщение. У бота, чата и сообщения есть `updated_at`. Если два устройства сохранили одну сущность, на сервере остаётся более поздняя запись.

Метки времени хранятся в UTC. Кабинет показывает их в часовом поясе браузера.

Внешние идентификаторы — UUID. Поля JSON — на английском, тексты интерфейса — на русском. У ошибки поле `code` на английском и поле `message` на русском. Кабинет показывает `message`.

Пределы полей:

- почта — 254 символа;
- имя профиля — 80, может быть пустым;
- имя бота — от 1 до 80;
- описание — 280, может быть пустым;
- сценарий — 16 000, может быть пустым;
- сообщение чата — 8 000.

Каждый вызов модели пишет отдельную запись квоты и увеличивает счётчик в одной транзакции. Единица списывается, только если адаптер вернул текст ответа. Если текста нет, счётчик не меняется, сообщение ассистента не пишется, в чат уходит ошибка с русским `message`. Перечень таких причин появится вместе с API агрегатора.

Таблицы рутин, библиотеки и каталога приходят миграциями своих checkpoint'ов. Записи хранилища в эту базу не попадают.

### Агрегатор

Агрегатор свой. Ключ лежит на сервере. Клиент имя модели не передаёт и не показывает. Юрисдикцию агрегатор не нарушает. Его API выдаётся отдельно. До этого в коде живёт внутренний контракт и заглушка.

Запрос checkpoint 1 содержит описание бота, сценарий, реплики `user` и `assistant` этого чата по порядку и признак `desktop_available`. Записи `error` в адаптер не отправляются. Пока рабочий десктоп не отметился, признак равен `false`. Служебный блок в чат не записывается.

Новые поля добавляются только в адаптер, когда API выдадут. Клиент, чат и квота от этого не меняются.

Заглушка отвечает фразой «Сейчас я на заглушке агрегатора и не вызываю модель.» Это текст ответа, поэтому она списывает одну единицу квоты.

### Исполнение

Решения владельца продукта 16 ноября 2026. Направление пластины — тонкое стекло экрана чатов. Финальные макеты готовит дизайнер на следующей неделе. Проверочный кабинет собирается из текущих экранов `mockup/`. Функциональность закрывает checkpoint. Замена вёрстки на макеты дизайнера API, данные и правила этой очереди не меняет. Регистрация и вход в макете отсутствуют и собираются из полей экрана тарифа в его текущем виде. Прототипная шапка макета в кабинет не входит.

На тарифе одна карточка, без названия и цены. Числа 500 и 5 остаются в конфиге сервера и на карточке не пишутся. Кнопки «Оплатить» нет. Выход есть на тарифе, в списке, на карточке и в чате.

До подтверждения почты прямой заход на список, карточку и чат возвращает на тариф. Вход при неподтверждённой почте открывает тариф. Вход при подтверждённой открывает пустой список. Неизвестная почта и неверный пароль отвечают одним текстом: «Почта или пароль не сходятся».

Подтверждение делает токен из ссылки, cookie для этого не нужен. Действительный токен подтверждает почту и включает период. Если сессия этой учётной записи уже есть, кабинет открывает список ботов. Если сессии нет, кабинет открывает вход. Недействительный токен почту не подтверждает. При открытой сессии человек остаётся на тарифе, без сессии попадает на вход. В обоих случаях виден текст «Ссылка больше не действует».

В журнал сервера пишется абсолютный адрес ссылки и почта. Пароль в журнал не пишется. В базе хранится хеш токена.

Кабинет ходит в JSON с того же origin. Поля ниже — на английском, тексты `message` — на русском.

- `POST /api/register` — почта и пароль, открывает сессию. Занятая почта: `email_taken`, «Эта почта уже зарегистрирована». Пароль вне правил: `invalid_password`.
- `POST /api/login` — почта и пароль, открывает новую сессию. Неизвестная почта и неверный пароль: `invalid_credentials`.
- `POST /api/logout` — удаляет только текущую сессию.
- `GET /api/me` — учётная запись, признак подтверждения, период и счётчик квоты.
- `POST /api/confirmation` — новая ссылка для неподтверждённой сессии, прежняя гаснет.
- `GET /api/confirm-email?token=` — подтверждение по ссылке. Проверка Origin на этот запрос не ставится: ссылку открывают из журнала.
- `GET /api/bots`, `POST /api/bots` — список и создание. Создание сразу заводит основной чат.
- `GET /api/bots/{id}`, `PATCH /api/bots/{id}` — карточка: имя, цвет, значок, описание, сценарий.
- `GET /api/bots/{id}/messages`, `POST /api/bots/{id}/messages` — один основной чат.

Пока почта не подтверждена, запросы ботов и чата отвечают `email_unconfirmed`. Клиент имя модели не передаёт. В адаптер уходят описание, сценарий, реплики `user` и `assistant` по порядку и `desktop_available: false`. Записи `error` в чате остаются и в адаптер не отправляются. Если адаптер вернул пустой текст, в чат пишется `error`, счётчик не меняется. Код этой причины внутри checkpoint — `empty_model_response`, текст — «Ответ модели не пришёл.» Перечень причин агрегатора заменит его, когда API выдадут.

Квота кончилась: сообщение пользователя сохраняется, адаптер не вызывается, в чат пишется `error` с текстом «Квота на период закончилась.», счётчик не меняется. Этот текст калибруется перед релизом вместе с формулой остатка.

Cookie сессии называется `session`. В ней лежит только идентификатор сессии.

Ссылка подтверждения хранит хеш токена, срок и момент гашения. Сессия хранит учётную запись и время последнего успешного запроса. У сообщения есть роль `user`, `assistant` или `error`. Цвет и значок бота берутся из набора макета.

Порядок работ: проект uv и PostgreSQL в Docker, миграция, регистрация и ссылка, боты с чатом и заглушкой, кабинет из текущего макета, pytest из раздела готовности.

### Готовность

Checkpoint закрыт, когда pytest проходит регистрацию, отказ повторной и просроченной ссылки, выпуск новой ссылки взамен прежней, подтверждение почты, вход, выход, запрет списка ботов до подтверждения, создание бота, одно сообщение через заглушку и списание квоты с 500 до 499. Пустой ответ адаптера квоту не меняет.

## Десктоп

Сначала macOS. Windows повторяет то же после неё.

Процесс на Python 3.15. Окно — pywebview 6.2: на macOS это WKWebView, на Windows — WebView2. Окно грузит тот же кабинет. Закрытие окна прячет его, процесс остаётся. Выход из трея и команда «Выйти» процесс останавливают.

В начале этой вехи проверяется импорт pywebview на Python 3.15. Если системные биндинги не встают, окно собирается на PySide6 6.12.

Браузер — установленный Google Chrome. Приложение хранит куки в своём каталоге профиля и ведёт браузер через Playwright. Каталог живёт между запусками. Если Chrome не установлен, в настройках выбирается другой установленный Chromium-браузер, начиная с Edge.

Пароли на macOS лежат в Ключнице. Экран пароля ходит только на `127.0.0.1` процесса десктопа. В PostgreSQL и на Origin кабинета пароль не попадает.

Рабочий десктоп присылает пульс каждые 30 секунд и свою временную зону. Время рутины — местное время этой зоны. В назначенную минуту сервер ждёт 60 секунд, что десктоп заберёт запуск. Не забрал — сервер пишет пропуск в основной чат. На macOS показывается местное уведомление. Пуш телефона остаётся на вехе телефона.

Второй checkpoint: из чата выполняется одно действие в этом браузере. Пароль остаётся на машине.

Третий checkpoint: рутина идёт при скрытом окне. Если процесс мёртв, сервер записывает пропуск.

## Следующие вехи

После первого checkpoint это отдельные вехи. Порядок между ними выбирается, когда checkpoint закрыт. Правила MVP до того не меняются.

- Дополнительные чаты.
- Библиотека.
- Каталог.
- Опасное «Да» и канал ответа между телефоном и десктопом.
- Главный бот.
- Второй десктоп.
- Телефон.
- Платёжный провайдер.
- Почтовый провайдер.
- Общий хостинг.
- Публичный сайт. Он делается перед релизом и кабинет его не ждёт.
- Полная схема API агрегатора и перечень причин, при которых текста ответа нет.
