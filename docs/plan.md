# План разработки

Технические решения и порядок работ. Поведение продукта — в [глоссарии](glossary.md), [модели](domain.md), [потоках](flows.md) и [границе MVP](out-of-scope.md).

<a id="stack"></a>

## Стек

Сервер и десктоп пишутся на Python 3.15. В `requires-python` стоит `>=3.15,<3.16`. Телефон — отдельное приложение. В третий checkpoint оно не входит и ждёт дизайн. Windows-клиент в этот checkpoint не входит.

Сервер — FastAPI. Кабинет и будущий десктоп ходят в один JSON API. FastAPI отдаёт статику кабинета и JSON с одного origin.

База — PostgreSQL. Таблицы ведёт SQLAlchemy 2.0, миграции — Alembic, драйвер — psycopg 3. Поддержка Python 3.15 у SQLAlchemy есть с 2.0.52.

Локально PostgreSQL поднимается в Docker, сервер запускается через uv. Общий стенд — чанк третьего checkpoint.

Пароль хранится хешем Argon2 через `pwdlib` 0.4.0.

Репозиторий один.

- `server/` — сервер на uv.
- `web/` — кабинет: HTML, CSS и JS из макета, без прототипной шапки.
- `mockup/` — просмотр макета. Сервер его не отдаёт.
- `desktop/` — macOS. Windows-клиент этим планом не закладывается.

<a id="checkpoint-1"></a>

## Первый checkpoint

Кабинет в браузере. Экраны: регистрация, вход, тариф, список ботов, карточка, чат. Карточка сохраняет имя, аватар, описание и сценарий. Набор аватара берётся из макета. Пара по умолчанию — цвет «Ржавый» (`#c85a12`) и значок «Искра» (`spark`). Экран пароля подключается на macOS вместе с хранилищем. Рутина, библиотека, главный бот, «Да» и «Нет», бейдж рабочего десктопа и оплата в этот checkpoint не входят.

### Путь пользователя

Регистрация по почте и паролю сразу открывает сессию. До подтверждения почты виден только экран тарифа. Ссылка подтверждения одноразовая и живёт 24 часа. В разработке она берётся из журнала сервера. Письмо наружу уходит в чанке почты третьего checkpoint.

Повторное открытие и открытие после 24 часов почту не подтверждают. На тарифе виден текст «Ссылка больше не действует». Кнопка «Прислать новую» доступна, пока почта не подтверждена: она пишет в журнал новую ссылку и гасит прежнюю. В первом checkpoint письмо наружу не отправляется.

Почта сохраняется без пробелов по краям и в нижнем регистре. Уникальность проверяется по этому виду.

После подтверждения в разработке период подписки становится активным. Оплата встаёт на это место в чанке оплаты третьего checkpoint, как в [потоках](flows.md).

Период — календарный месяц от даты старта. Старт 16 ноября кончается 16 декабря. Если этого числа в месяце нет, период кончается в последний день месяца.

В конфиге разработки один тариф без названия и цены: 500 запросов к модели и 5 рутин на период. Перед релизом числа, название и цену задаёт владелец продукта.

Дальше открывается пустой список ботов. С экрана тарифа и из кабинета доступен выход. Он удаляет только текущую сессию.

Имя профиля хранится в учётной записи, до 80 символов, и может быть пустым. Экран его правки в этот checkpoint не входит.

### Сессия и пароль

Каждый вход создаёт свою сессию. Кабинет и будущий десктоп могут быть в аккаунте одновременно. Выход на одном устройстве другое не разлогинивает.

Сессия живёт 30 дней с последнего успешного запроса.

Пароль — от 8 до 128 символов. В нём есть хотя бы одна цифра `0–9` и хотя бы один знак из набора `` !@#$%^&*()-_=+[]{}:;,.? ``.

Идентификатор сессии лежит в PostgreSQL. Браузер получает только его в cookie `HttpOnly` и `SameSite=Lax`. JavaScript cookie не читает. Изменяющий запрос принимается только с Origin нашего сервера. Флаг `Secure` включается на общем стенде.

### Данные

Первая миграция: учётная запись, ссылка подтверждения, сессия, период подписки, счётчик квоты, запись списания, бот, чат, сообщение. У бота, чата и сообщения есть `updated_at`. Если два устройства сохранили одну сущность, на сервере остаётся более поздняя запись.

Метки времени хранятся в UTC. Кабинет показывает их в часовом поясе браузера.

Внешние идентификаторы — UUID. Поля JSON — на английском, тексты интерфейса — на русском. У ошибки поле `code` на английском и поле `message` на русском. Кабинет показывает `message`.

Пределы полей:

- почта — 254 символа;
- имя профиля — 80, может быть пустым;
- имя бота — от 1 до 80;
- описание — 280, может быть пустым;
- сценарий — 16 000, может быть пустым;
- сообщение чата — 8 000.

Каждый вызов модели пишет отдельную запись квоты и увеличивает счётчик в одной транзакции. Единица списывается, только если адаптер вернул текст ответа. Если текста нет, счётчик не меняется, сообщение ассистента не пишется, в чат уходит ошибка с русским `message`. Перечень таких причин появится вместе с API агрегатора.

Таблицы рутин, библиотеки и каталога приходят миграциями своих checkpoint'ов. Записи хранилища в эту базу не попадают.

### Агрегатор

Агрегатор свой. Ключ лежит на сервере. Клиент имя модели не передаёт и не показывает. Юрисдикцию агрегатор не нарушает. Его API выдаётся отдельно. До этого в коде живёт внутренний контракт и заглушка.

Запрос checkpoint 1 содержит описание бота, сценарий, реплики `user` и `assistant` этого чата по порядку и признак `desktop_available`. Записи `error` в адаптер не отправляются. Пока рабочий десктоп не отметился, признак равен `false`. Служебный блок в чат не записывается.

Новые поля добавляются только в адаптер, когда API выдадут. Клиент, чат и квота от этого не меняются.

Заглушка отвечает фразой «Сейчас я на заглушке агрегатора и не вызываю модель.» Это текст ответа, поэтому она списывает одну единицу квоты.

<a id="checkpoint-1-build"></a>

### Исполнение

Решения владельца продукта 16 ноября 2026. Направление пластины — тонкое стекло экрана чатов. Финальные макеты готовит дизайнер на следующей неделе. Проверочный кабинет собирается из текущих экранов `mockup/`. Функциональность закрывает checkpoint. Замена вёрстки на макеты дизайнера API, данные и правила этой очереди не меняет. Регистрация и вход в макете отсутствуют и собираются из полей экрана тарифа в его текущем виде. Прототипная шапка макета в кабинет не входит.

На тарифе одна карточка, без названия и цены. Числа 500 и 5 остаются в конфиге сервера и на карточке не пишутся. Кнопки «Оплатить» нет. Выход есть на тарифе, в списке, на карточке и в чате.

До подтверждения почты прямой заход на список, карточку и чат возвращает на тариф. Вход при неподтверждённой почте открывает тариф. Вход при подтверждённой открывает пустой список. Неизвестная почта и неверный пароль отвечают одним текстом: «Почта или пароль не сходятся».

Подтверждение делает токен из ссылки, cookie для этого не нужен. Действительный токен подтверждает почту и включает период. Если сессия этой учётной записи уже есть, кабинет открывает список ботов. Если сессии нет, кабинет открывает вход. Недействительный токен почту не подтверждает. При открытой сессии человек остаётся на тарифе, без сессии попадает на вход. В обоих случаях виден текст «Ссылка больше не действует».

В журнал сервера пишется абсолютный адрес ссылки и почта. Пароль в журнал не пишется. В базе хранится хеш токена.

Кабинет ходит в JSON с того же origin. Поля ниже — на английском, тексты `message` — на русском.

- `POST /api/register` — почта и пароль, открывает сессию. Занятая почта: `email_taken`, «Эта почта уже зарегистрирована». Пароль вне правил: `invalid_password`.
- `POST /api/login` — почта и пароль, открывает новую сессию. Неизвестная почта и неверный пароль: `invalid_credentials`.
- `POST /api/logout` — удаляет только текущую сессию.
- `GET /api/me` — учётная запись, признак подтверждения, период и счётчик квоты.
- `POST /api/confirmation` — новая ссылка для неподтверждённой сессии, прежняя гаснет.
- `GET /api/confirm-email?token=` — подтверждение по ссылке. Проверка Origin на этот запрос не ставится: ссылку открывают из журнала.
- `GET /api/bots`, `POST /api/bots` — список и создание. Создание сразу заводит основной чат.
- `GET /api/bots/{id}`, `PATCH /api/bots/{id}` — карточка: имя, цвет, значок, описание, сценарий.
- `GET /api/bots/{id}/messages`, `POST /api/bots/{id}/messages` — один основной чат.

Пока почта не подтверждена, запросы ботов и чата отвечают `email_unconfirmed`. Клиент имя модели не передаёт. В адаптер уходят описание, сценарий, реплики `user` и `assistant` по порядку и `desktop_available: false`. Записи `error` в чате остаются и в адаптер не отправляются. Если адаптер вернул пустой текст, в чат пишется `error`, счётчик не меняется. Код этой причины внутри checkpoint — `empty_model_response`, текст — «Ответ модели не пришёл.» Перечень причин агрегатора заменит его, когда API выдадут.

Квота кончилась: сообщение пользователя сохраняется, адаптер не вызывается, в чат пишется `error` с текстом «Квота на период закончилась.», счётчик не меняется. Этот текст калибруется перед релизом вместе с формулой остатка.

Cookie сессии называется `session`. В ней лежит только идентификатор сессии.

Ссылка подтверждения хранит хеш токена, срок и момент гашения. Сессия хранит учётную запись и время последнего успешного запроса. У сообщения есть роль `user`, `assistant` или `error`. Цвет и значок бота берутся из набора макета.

<a id="checkpoint-1-chunks"></a>

### Чанки

Пять чанков идут по порядку. Следующий начинается, когда предыдущий закрыт своей проверкой. Замена вёрстки на макеты дизайнера в эти чанки не входит. Весь checkpoint закрывается pytest из раздела готовности.

**1. Каркас**

- Завести `server/` на uv с `requires-python >=3.15,<3.16` и FastAPI.
- Поднять PostgreSQL в Docker. Сервер запускается через uv на хосте.
- Подключить SQLAlchemy 2.0 и Alembic.
- Вынести в конфиг один тариф: 500 запросов и 5 рутин, без названия и цены.
- Отдавать проверку живости и каталог `web/` с одного origin.

Готово, когда сервер поднимается, подключается к локальной базе, а проверка живости отвечает.

**2. Регистрация и сессия**

- Миграция учётной записи и сессии. Сессия хранит учётную запись и время последнего успешного запроса.
- Хеш пароля — Argon2 через pwdlib. Почта нормализуется, уникальность проверяется по этому виду. Пароль проверяется по правилам этого checkpoint.
- Сделать `POST /api/register`, `POST /api/login`, `POST /api/logout` и `GET /api/me`.
- Cookie `session`: `HttpOnly`, `SameSite=Lax`, без `Secure`. В ней только идентификатор сессии. Изменяющий запрос принимается с Origin нашего сервера. Выход удаляет только текущую сессию.

Готово, когда pytest проходит регистрацию, занятую почту, пароль вне правил, вход, одинаковый отказ для неизвестной почты и неверного пароля, выход и сохранение второй сессии после выхода из первой.

**3. Подтверждение почты**

- Миграция ссылки: хеш токена, срок 24 часа и момент гашения.
- При регистрации и по «Прислать новую» писать в журнал абсолютный адрес и почту. Пароль в журнал не писать.
- Сделать `GET /api/confirm-email?token=` без проверки Origin. Действительный токен подтверждает почту и включает период. Если сессия этой учётной записи уже есть, ответ ведёт на список ботов, если её нет — на вход.
- Повторное открытие и открытие после 24 часов почту не подтверждают и оставляют текст «Ссылка больше не действует».
- Сделать `POST /api/confirmation` для неподтверждённой сессии: прежняя ссылка гаснет, в журнале появляется новая.
- До подтверждения запросы ботов и чата отвечают `email_unconfirmed`.

Готово, когда pytest проходит подтверждение, отказ повторной и просроченной ссылки, выпуск новой ссылки взамен прежней и запрет списка ботов до подтверждения.

**4. Бот, чат и квота**

- Миграция периода подписки, счётчика квоты, записи списания, бота, чата и сообщения. У сообщения роль `user`, `assistant` или `error`.
- `POST /api/bots` сразу заводит основной чат. Цвет и значок берутся из набора макета. Без выбора ставятся «Ржавый» и «Искра». Пределы полей — из раздела данных.
- Сделать `GET /api/bots`, `GET /api/bots/{id}`, `PATCH /api/bots/{id}`, `GET /api/bots/{id}/messages` и `POST /api/bots/{id}/messages`.
- В адаптер уходят описание, сценарий, реплики `user` и `assistant` по порядку и `desktop_available: false`. Заглушка отвечает фразой из раздела агрегатора. Списание и запись квоты пишутся в одной транзакции.
- Пустой текст адаптера пишет в чат `error` «Ответ модели не пришёл.» с кодом `empty_model_response` и счётчик не меняет.
- При нулевой квоте сообщение пользователя сохраняется, адаптер не вызывается, в чат пишется «Квота на период закончилась.», счётчик не меняется.

Готово, когда pytest проходит создание бота, одно сообщение через заглушку, списание квоты с 500 до 499, пустой ответ адаптера и отказ при исчерпанной квоте.

**5. Кабинет**

- Перенести в `web/` текущие экраны тарифа, списка, карточки и чата из `mockup/` без прототипной шапки.
- Собрать регистрацию и вход из полей экрана тарифа.
- Убрать рутину, библиотеку, главного бота, «Да» и «Нет», бейдж рабочего десктопа и кнопку «Оплатить». На тарифе оставить одну карточку без названия, цены и чисел квоты.
- Связать экраны с API чанков 2–4. До подтверждения открыт тариф и кнопка «Прислать новую». После подтверждения открывается пустой список, из него — создание, карточка и один чат.
- Показать на экранах поле `message`. Выход поставить на тарифе, в списке, на карточке и в чате.

Готово, когда эти экраны проводят регистрацию, подтверждение по ссылке из журнала, вход, выход, создание бота и одно сообщение заглушки. Pytest из раздела готовности к этому моменту зелёный.

### Готовность

Checkpoint закрыт, когда pytest проходит регистрацию, отказ повторной и просроченной ссылки, выпуск новой ссылки взамен прежней, подтверждение почты, вход, выход, запрет списка ботов до подтверждения, создание бота, одно сообщение через заглушку и списание квоты с 500 до 499. Пустой ответ адаптера квоту не меняет.

<a id="desktop"></a>

## Десктоп

Сначала macOS. Windows-клиент повторяет то же после третьего checkpoint и в его чанки не нарезан.

Процесс на Python 3.15. Окно — pywebview 6.2: на macOS это WKWebView, на Windows — WebView2. Окно грузит тот же кабинет. Закрытие окна прячет его, процесс остаётся. Выход из трея и команда «Выйти» процесс останавливают.

В начале этой вехи проверяется импорт pywebview на Python 3.15. Если системные биндинги не встают, окно собирается на PySide6 6.12.

Браузер — установленный Google Chrome. Приложение хранит куки в своём каталоге профиля и ведёт браузер через Playwright. Каталог живёт между запусками. Если Chrome не установлен, в настройках выбирается другой установленный Chromium-браузер, начиная с Edge.

Пароли на macOS лежат в Ключнице. Экран пароля ходит только на `127.0.0.1` процесса десктопа. В PostgreSQL и на Origin кабинета пароль не попадает.

Рабочий десктоп присылает пульс каждые 30 секунд и свою временную зону. Время рутины — местное время этой зоны. В назначенную минуту сервер ждёт 60 секунд, что десктоп заберёт запуск. Не забрал — сервер пишет пропуск в основной чат. На macOS показывается местное уведомление. Пуш телефона ждёт мобильное приложение.

Пароль остаётся на машине. Это закрывает чанк 4 второго checkpoint. Одно действие из чата в браузере — чанк 1 третьего checkpoint. Рутина при скрытом окне и пропуск, если процесс мёртв, — чанк 3 третьего checkpoint.

<a id="checkpoint-2-chunks"></a>

### Чанки второго checkpoint

Второй checkpoint — macOS. Окно грузит тот же кабинет. Браузер — установленный Google Chrome, куки в каталоге профиля приложения, ведёт его Playwright. Пароль лежит в Ключнице и на сервер не уходит. Рутина, пропуск, «Да» и «Нет», телефон, библиотека, каталог, главный бот и оплата в эти чанки не входят.

Четыре чанка идут по порядку. Следующий начинается, когда предыдущий закрыт своей проверкой.

**1. Процесс и окно**

- Каталог `desktop/` на Python 3.15.
- В начале проверяется импорт pywebview 6.2. Если системные биндинги не встают, окно собирается на PySide6 6.12.
- Окно грузит кабинет.
- Закрытие прячет окно, процесс остаётся. Выход из трея и команда «Выйти» процесс останавливают.

Готово, когда на этом Mac окно показывает кабинет, закрытие его прячет, а «Выйти» процесс гасит.

**2. Рабочий десктоп**

- Первый десктоп, где пользователь вошёл, становится рабочим.
- Он присылает пульс каждые 30 секунд и свою временную зону.
- Пока пульса нет, `desktop_available` остаётся `false`. Браузерная задача при этом отвечает «компьютер недоступен».

Готово, когда без пульса чат получает этот текст, а после пульса признак становится `true`.

**3. Браузер**

- Приложение открывает установленный Google Chrome через Playwright и хранит куки в своём каталоге профиля.
- Каталог живёт между запусками.
- Если Chrome не установлен, в настройках выбирается другой установленный Chromium-браузер, начиная с Edge.

Готово, когда повторный запуск видит тот же каталог профиля.

**4. Пароль на машине**

- Пароль на macOS лежит в Ключнице.
- Экран пароля ходит только на `127.0.0.1` процесса десктопа.
- В PostgreSQL и на Origin кабинета пароль не попадает.

Готово, когда пароль читается из Ключницы локальным экраном и не появляется в базе, в журнале сервера и в запросе кабинета.

<a id="later"></a>

## Третий checkpoint

Решение владельца продукта 18 ноября 2026. В этот checkpoint входит всё, что осталось в [глоссарии](glossary.md), [модели](domain.md), [потоках](flows.md) и [границе MVP](out-of-scope.md), кроме Windows-клиента, мобильного приложения, публичного сайта и вебхуков. Windows повторяет macOS после этого checkpoint и чанками здесь не нарезан. Мобильное приложение ждёт дизайн. Публичный сайт отложен, кабинет его не ждёт.

После последнего чанка нового checkpoint нет. Дальше проверка и докрутка. Правила MVP, открытые вопросы и граница версии этим разрезом не меняются. Замена вёрстки на макеты дизайнера в чанки не входит. Вебхуки в этот checkpoint не входят: они описаны отдельным срезом.

Чанки идут по порядку. Следующий начинается, когда предыдущий влит в `main`. Задача — один пункт чанка и один коммит. Пункт «Готово, когда» остаётся воротами всего чанка.

Кабинет добирает экраны из текущего `mockup/` без прототипной шапки. На тарифе по-прежнему одна карточка без названия, цены и чисел квоты, пока владелец продукта их не задал.

<a id="checkpoint-3-chunks"></a>

### Чанки третьего checkpoint

**1. Одно действие в браузере**

- Сообщение, в котором пользователь назвал адрес, рабочий десктоп открывает в браузере приложения.
- Текст страницы приходит на сервер в ответе десктопа и отдельной записью в базу не кладётся. В адаптер он входит в чанке агрегатора.
- В чат записывается ответ адаптера. Пока отвечает заглушка, это её фраза. Записи `error` в адаптер не уходят.
- Пока пульса нет, чат получает «компьютер недоступен», и браузер для этого сообщения не открывается.
- Пароль, запись хранилища и куки не попадают в запрос кабинета, в PostgreSQL и в журнал сервера.
- Заглушка списывает одну единицу квоты, если вернула текст. Пустой текст квоту не меняет.
- Нажатия и ввод сверх открытия адреса в этот чанк не входят. Вход с паролем входит в чанк хранилища. Шаг из закрытого списка «Да» входит в чанк опасного действия.

Готово, когда pytest открывает названный адрес, пишет в тот же чат фразу заглушки, без пульса отвечает «компьютер недоступен» и не находит пароль и куки на сервере.

**2. Хранилище**

- Запись — сайт, логин и пароль. На один сайт записей может быть несколько. Запись общая или личная для одного бота.
- Запись живёт на рабочем десктопе. Пароля нет в PostgreSQL, в журнале сервера, в чате, в контексте модели и в адаптере.
- Запись из профиля по умолчанию общая. Запись, которую запросил бот, по умолчанию личная. До сохранения её можно сделать общей.
- Экран хранилища пароль не показывает. Ручное действие одно — скопировать. Экран берётся из экрана пароля макета, без прототипной шапки.
- Вход в живом чате идёт по порядку из модели: открытая сессия пароль не трогает; при запросе входа берётся запись с этим сайтом и логином из сценария; если подходят несколько записей или логин не назван, бот спрашивает в чате и не вводит пароль, пока пользователь не выберет; если записи нет, бот показывает защищённую форму, и после отправки модель узнаёт только то, что доступ сохранён.
- Пользователь добавляет, заменяет и удаляет запись. Бот записи не меняет и не удаляет. Удаление бота удаляет его личные записи и оставляет общие.
- Запись на сервер и на другой десктоп не копируется.

Готово, когда pytest читает пароль только на десктопе, проводит вход сохранённой записью и не находит пароль в базе, в журнале и в запросе кабинета.

**3. Рутина, скрытое окно и пропуск**

- Миграция рутины: бот, дни недели и одно время. Своего текста у рутины нет. Без сценария рутина не создаётся. Лимит — 5 из конфига тарифа. Удаление рутины освобождает место.
- Время — местная зона рабочего десктопа.
- Пауза отменяет будущие запуски и пропуском не считается.
- Закрытое окно процесс не гасит, и запуск может идти. «Выйти» и выход из трея процесс гасят.
- Выход из аккаунта на рабочем десктопе останавливает рутины и роль рабочего не снимает.
- В назначенную минуту сервер ждёт 60 секунд, что десктоп заберёт запуск. Не забрал — в основной чат пишется пропуск. Позже этот запуск не выполняется.
- Пропуск пишется, когда к концу 60 секунд рутина могла идти и запуск не забран. Пауза и выход на эту местную дату ставят отметку «запуск отменён». Сверка после снятия паузы или нового входа отметку видит и пропуск не пишет. Следующий запуск — только следующая назначенная минута.
- Процесса нет или рабочего десктопа нет — рутина не идёт, в основной чат пишется пропуск.
- Пока подписка неактивна, рутина не стартует. В разработке период по-прежнему включается подтверждением почты. Чанк оплаты заменяет это включение, когда в конфиге есть название и цена.
- Если сценария недостаточно, сайт не открылся или вход не удался, запуск завершается с причиной в основном чате. Сам он не повторяется.
- Во время рутины бот не спрашивает, какую запись хранилища выбрать. Если без выбора войти нельзя, запуск завершается с причиной.
- Запуск читает текущий сценарий целиком. Каждый вызов модели списывает единицу квоты. Если квота кончилась посреди запуска, запуск останавливается, в основной чат пишется «Квота на период закончилась.», и счётчик дальше не растёт.
- В кабинете дни недели и одно время показываются так, как они собраны в макете, без прототипной шапки.

Готово, когда pytest создаёт рутину, проводит один запуск при скрытом окне, пишет пропуск, если десктоп запуск не забрал, и не создаёт рутину без сценария.

**4. Очередь и «Проверить сейчас»**

- Браузером занят один бот. Вторая рутина ждёт. Первой идёт рутина, созданная раньше. Каждая затем выполняет свой сценарий целиком.
- Если день и время уже заняты другой рутиной аккаунта, кабинет предупреждает до сохранения. Пользователь может оставить это время.
- Когда ожидание начинается, в основной чат ждущего бота приходит одно сообщение, кого он ждёт. Пуша об очереди нет.
- Сообщение боту, который занят браузером, ждёт. Сообщение другому боту, которому браузер не нужен, уходит сразу.
- «Проверить сейчас» выполняет текущий сценарий, пишет результат в основной чат, в очереди не обгоняет текущий запуск и тратит квоту вызовами модели.

Готово, когда pytest проводит две рутины одного времени по порядку создания и показывает предупреждение до сохранения.

**5. Пуш на macOS**

- Местное уведомление уходит, когда запуск завершился, сорвался или пропущен.
- Нажатие открывает основной чат этого бота. Скрытое окно уведомление открывает так же.
- Обычная реплика и сообщение об очереди уведомление не вызывают.
- Пуш телефона в этот чанк не входит. Он ждёт мобильное приложение.

Готово, когда pytest фиксирует уведомление для завершения, сбоя и пропуска и не фиксирует его для обычной реплики.

**6. Опасное «Да» и «Нет»**

- Закрытый список: отправить, заплатить, удалить, опубликовать или сменить пароль. Чтение почты и вход сохранённым доступом в список не входят.
- В основном чате сообщение называет действие и даёт «Да» и «Нет». Кнопки берутся из текущего макета.
- «Да» выполняет шаг. «Нет» пропускает этот шаг. Бот доделывает остальное и пишет, чего не сделал.
- Пока ответа нет, следующий запуск этой рутины не начинается. Срока ожидания нет.
- Пауза снимает ожидание и завершает этот запуск. Пропуском это не считается.
- «Да» и «Нет» нажимает пользователь в кабинете. Нажатие лежит в чате. Рабочий десктоп продолжает тот же запуск, если ещё ждёт и пульс жив.
- Нажатие с телефона ждёт мобильное приложение и в этот чанк не входит.
- Если пульс пропал, пока запуск ждёт «Да», запуск завершается с причиной. Уходит уведомление о сбое. Это не пропуск. После нового пульса запуск сам не продолжается. Позднее «Да» ничего не начинает.
- Главный бот эти кнопки не нажимает.
- К ожидающим «Да» добавлено местное уведомление. Нажатие открывает основной чат этого бота.

Готово, когда pytest не выполняет шаг из списка без «Да», выполняет его после «Да», пропускает шаг после «Нет» и завершает запуск, если пульс пропал в ожидании.

**7. Дополнительные чаты**

- Пользователь добавляет дополнительный чат. Он пустой. Сценарий тот же. История не копируется.
- Основной чат удалить нельзя. Дополнительный можно.
- Результат разового поручения остаётся в том чате, где его попросили, и в основной чат не копируется.
- Удаление дополнительного чата библиотеку не удаляет.

Готово, когда pytest создаёт пустой дополнительный чат, отказывает в удалении основного и оставляет ответ разового поручения в дополнительном чате.

**8. Сценарий из чата**

- Прямая правка на карточке сценарий уже сохраняет. Этот чанк добавляет путь из чата.
- Пользователь просит сохранить правила. В чат попадает новый текст целиком.
- Запись заменяет прежний сценарий только после подтверждения. Без подтверждения сценарий остаётся прежним.
- Прошлая переписка не переписывается. Следующее сообщение и следующая рутина идут по новому тексту.
- Просьба из дополнительного чата меняет тот же сценарий бота.
- Заглушка текст сценария не сочиняет. Подтверждение записывает текст, который уже лежит в сообщении ассистента.

Готово, когда pytest меняет сценарий после подтверждения и оставляет прежний текст, если подтверждения не было.

**9. Библиотека**

- Файл, который создал бот, лежит в библиотеке этого бота и приложен к ответу в том чате, где его попросили.
- В этой версии файл — xlsx. Формат остаётся открытым вопросом из границы MVP. Чанк его не меняет.
- Анализ и перевод приходят текстом, без файла.
- Пользователь открывает и удаляет файл. Бот файлы не удаляет. Свой файл загрузить нельзя.
- Файл хранится на сервере и скачивается на других устройствах аккаунта. К хранилищу паролей он не относится.
- Удаление дополнительного чата файл из библиотеки не удаляет. Удаление бота библиотеку удаляет.
- Заглушка файл не возвращает. Если адаптер вернул xlsx вместе с текстом, кабинет кладёт его в библиотеку и прикладывает к ответу.

Готово, когда pytest сохраняет xlsx в библиотеку и в ответ чата, удаляет его действием пользователя и оставляет файл после удаления дополнительного чата.

**10. Каталог**

- Элемент каталога — название, адрес и короткое описание. Список пуст, пока пользователь не добавит сайт. Готового списка нет. Свой сайт добавляется так же. Отдельного API у сайта нет.
- Подключение даётся всем ботам или выбранным. Подключение «всем» включает и ботов, созданных позже.
- В рутине бот без подключения не открывает этот адрес. Запуск завершается с причиной. В разовом поручении бот открывает адрес, если пользователь его назвал.
- Сайт вне каталога открывается, если его назвали сценарий или пользователь.
- Подключение не закрывает остальные адреса.
- Удаление бота оставляет подключение «всем». Подключение только этому боту исчезает.
- Каталог открывается из профиля. Отдельного кадра каталога в макете нет. Кабинет собирает экран из полей карточки и списка, без прототипной шапки.

Готово, когда pytest добавляет сайт, подключает его выбранному боту и завершает рутину этого адреса у бота без подключения.

**11. Главный бот**

- Главный один на аккаунт. Назначение нового снимает прежнее. Назначение можно снять. Пока главного нет, отчётов нет.
- Отчёт — сообщение в основном чате главного, когда рутина другого бота завершилась, пропущена или ждёт «Да». Своя рутина главного отчёт не создаёт.
- Отдельного дайджеста нет. Как собрать сводку, написано в сценарии главного.
- Поручение главного — сообщение в основном чате другого бота. Оно сразу начинает ход того бота и сценарий не меняет.
- Вопрос того бота остаётся в его основном чате и в чат главного не копируется.
- Главный не нажимает «Да» и не видит личные записи других ботов.

Готово, когда pytest назначает одного главного, пишет ему отчёт о пропуске чужой рутины, не пишет отчёт о его собственной рутине и не даёт ему нажать «Да».

**12. Второй десктоп**

- Вход на другом десктопе показывает с сервера ботов, чаты, сценарии, рутины и библиотеку.
- Хранилище, куки и сессии браузера не копируются.
- Этот десктоп рутины не запускает, пока пользователь не перенёс на него роль рабочего.
- Уже идущий запуск заканчивается на старом компьютере. Следующий запуск идёт на новом.
- Выход на втором десктопе рабочий десктоп не останавливает.
- Если два устройства сохранили одну сущность, на сервере остаётся более позднее сохранение. Экрана сравнения версий нет.
- Перенос роли находится в профиле.

Готово, когда pytest после переноса роли пускает следующую рутину на новом десктопе, оставляет хранилище на старом и не останавливает рабочий десктоп выходом на втором.

**13. Профиль и удаление аккаунта**

- Имя профиля правится из профиля. В нём до 80 символов, и оно может быть пустым.
- В профиле видны тариф и счётчик квоты периода. Формулу остатка чанк не задаёт.
- Удаление спрашивает подтверждение и не отменяется. Сервер удаляет ботов, чаты, рутины, библиотеку и подписку. Архива нет.
- При следующем запуске десктопа местное хранилище и сессии браузера стираются.
- Отдельного кадра профиля в макете нет. Экран собирается из полей тарифа и карточки, без прототипной шапки.

Готово, когда pytest меняет имя, удаляет аккаунт после подтверждения и на следующем запуске десктопа не находит местный пароль и каталог профиля браузера.

**14. Почта**

- Письмо со ссылкой подтверждения содержит абсолютный адрес и почту. Пароля в письме нет.
- Срок 24 часа, одноразовость и гашение прежней ссылки по «Прислать новую» остаются.
- В разработке приёмник письма — журнал сервера. Имя провайдера чанк не выбирает. Когда приёмник задан в конфиге, то же письмо уходит туда.
- Повторное открытие и просрочка оставляют текст «Ссылка больше не действует».

Готово, когда pytest находит в письме адрес и почту, не находит пароль и гасит прежнюю ссылку новой.

**15. Оплата**

- До первой оплаты клиент показывает только экран тарифа. После успешной оплаты открывается пустой список ботов. Период стартует в дату оплаты и длится календарный месяц, как уже задано для периода.
- Отмена оставляет подписку активной до конца оплаченного периода. Неудачное продление делает её неактивной в конце периода.
- Пока подписка неактивна, пользователь открывает ботов, чаты и библиотеку и меняет имя, сценарий и расписание. Модель не вызывается. Рутина и «Проверить сейчас» не стартуют. В чат приходит сообщение, что подписка неактивна. Точный текст этого сообщения чанк не фиксирует.
- Название и цена берутся из конфига. Пока их нет, на тарифе одна карточка без названия, цены и кнопки «Оплатить», а период в разработке включается подтверждением почты.
- Когда название и цена заданы, период включает успешная оплата. Подтверждение почты само период не включает.
- Провайдера чанк не называет. Успех, отмена и неудачное продление приходят через адаптер оплаты.

Готово, когда pytest с названием и ценой в тестовом конфиге открывает список ботов после успешной оплаты и не стартует рутину после неудачного продления.

**16. Агрегатор**

- Ключ агрегатора лежит на сервере. Клиент имя модели не передаёт и не показывает. В журнале сервера имени модели нет.
- В адаптер уходят описание, сценарий, реплики `user` и `assistant` по порядку, `desktop_available` и текст страницы, которую бот прочитал для этого ответа. Отдельный журнал этого прохода не заводится.
- Пароль, запись хранилища и куки в адаптер не уходят.
- Пустой текст квоту не списывает и пишет в чат `error`. Пока выданной схемы нет, код причины остаётся `empty_model_response`, текст — «Ответ модели не пришёл.»
- Схему API чанк не придумывает. Когда схема лежит в репозитории, адаптер берёт её, а перечень причин пустого текста заменяет `empty_model_response`. Клиент, чат и квота от этого не меняются.
- До выданной схемы заглушка отвечает прежней фразой и списывает одну единицу, если вернула текст.

Готово, когда pytest передаёт в адаптер текст страницы, не передаёт пароль и имя модели и списывает квоту только при непустом тексте.

**17. Общий хостинг**

- Кабинет и JSON открываются с одного origin. На стенде у cookie `session` стоит `Secure`.
- PostgreSQL стенда, ключ агрегатора и приёмник почты задаются конфигом. Секреты в репозиторий не входят.
- Площадку чанк не выбирает.

Готово, когда при конфиге стенда pytest видит `Secure` у cookie сессии и один origin у кабинета и JSON, а в коммитах нет секрета.

<a id="after-checkpoint-3"></a>

## После третьего checkpoint

Когда чанк 17 влит в `main`, проверка и докрутка этих семнадцати чанков остаются. Новый checkpoint для них не нарезается. Вебхуки — отдельный срез после третьего checkpoint. Чанки 1–17 он не меняет.

Windows-клиент в план не заложен. Он повторяет уже собранный macOS и начнётся отдельным решением владельца продукта.

Мобильное приложение в план не заложено. Оно ждёт дизайн и начнётся отдельным решением владельца продукта. Пуш телефона, «Да» и «Нет» с телефона и поручение с телефона ждут вместе с ним.

Публичный сайт в план не заложен. Он отложен. Кабинет его не ждёт.

<a id="webhooks"></a>

## Вебхуки

Решение владельца продукта 20 ноября 2026. Срез после третьего checkpoint. Первый чанк начинается, когда чанк 17 третьего checkpoint влит в `main`. Чанки 1–17 не меняются. Новый checkpoint этот срез не открывает.

Чанки идут по порядку. Следующий начинается, когда предыдущий влит в `main`. Задача — один пункт чанка и один коммит. Пункт «Готово, когда» остаётся воротами всего чанка.

Кабинет добирает поля вебхука на карточке бота. Отдельного кадра в макете нет, прототипной шапки нет.

<a id="webhook-chunks"></a>

### Чанки

**1. Входящий адрес**

- Секретный адрес создаётся вместе с ботом и хранится на сервере так, чтобы карточка показала его снова. Секрет выбирает сервер. Клиент свой секрет не присылает. В журнал адрес не пишется. Удаление бота и удаление аккаунта удаляют адрес.
- `GET` и `POST` `/api/hooks/{token}` принимаются без сессии и без проверки Origin. В основной чат пишется сообщение `user`: строка метода, ниже query, если она есть, затем тело, если оно есть. Заголовки в сообщение не входят. Пустой запрос тоже запускает ход.
- Ход идёт как разовое поручение. Рутина из запроса не создаётся и не стартует. Пауза рутин ход не останавливает. Неактивная подписка запрос принимает: модель не вызывается, в чат пишется то же сообщение, что и для обычной реплики.
- Тело длиннее 8 000 символов отвечает `400 payload_too_large`, «Сообщение длиннее 8 000 символов.» Тело не в UTF-8 отвечает `400 invalid_body`, «Тело запроса не текст.» Сообщение не пишется, ход не начинается.
- Неизвестный адрес отвечает `404 webhook_unknown`, «Адрес не найден.» Неподтверждённая почта отвечает `403 email_unconfirmed`, «Почта ещё не подтверждена.» Иначе сервер сразу отвечает `200` и `{ "ok": true }`. Текст модели остаётся в чате. Каждый запрос — отдельный ход.
- Карточка показывает адрес и даёт его скопировать и сменить. После смены прежний адрес мёртв.

Готово, когда pytest проводит GET и POST в основной чат, отвергает длинное и нетекстовое тело, неизвестный адрес и неподтверждённую почту и после смены адреса не принимает старый.

**2. Исходящий адрес**

- Карточка хранит один https-адрес публичного хоста и метод GET или POST. Локальный и частный адрес не сохраняется: `400 invalid_webhook_url`, «Адрес должен быть https и публичным.» Отдельного кадра в макете нет.
- Переключатель «Слать ответ» по умолчанию выключен и включается только вместе с таким адресом. Иначе `400 webhook_url_required`, «Сначала укажите адрес.»
- Пока переключатель включён, сервер один раз отправляет каждый непустой текст `assistant`. Сюда входят ответ в основном и дополнительном чате, результат рутины, «Проверить сейчас», текст, которым ход закончился после «Да», ответ на входящий вебхук и фраза заглушки. Пропуск, очередь, «компьютер недоступен», неактивная подписка, вопрос «Да» и «Нет» и роль `error` остаются в чате.
- POST отправляет текст как `text/plain; charset=utf-8`. GET кладёт его в параметр `text` и подменяет уже существующий `text`. Адрес в журнал не пишется. Квота за отправку не списывается. Рабочий десктоп для отправки не нужен.
- Одна попытка, ожидание 10 секунд, без редиректов. Адрес длиннее 8 000 символов, ответ не `2xx` или обрыв пишут в тот же чат `error` «Вебхук не отправлен.» Успешная отправка нового сообщения не пишет. Это `error` наружу не отправляется.

Готово, когда pytest сохраняет только публичный https, шлёт текст `assistant` выбранным методом и пишет «Вебхук не отправлен.» после неудачи, не отправляя это `error` повторно.
